# Verification

- `npm run typecheck`: passed during migration; final `npm run build` also passed Next.js's TypeScript check.
- `npm run lint`: passed on final application source.
- `npm test`: 6 tests passed, 0 failures.
- `npm run build`: passed on final source with Next.js 16.3.8 (webpack); all App Router pages generated.
- `npm run dev`: started successfully and printed `http://localhost:3000` after explicitly binding the dev hostname to localhost.

## Routes

`/` redirects to `/register`. `/register`, `/status`, `/login` and `/dashboard` are generated by the production build. The browser checked client transitions between those routes. Direct dashboard navigation in a new session redirected to login.

## Browser flow

The production preview exercised restaurant details (including multiple cuisines), location, five synthetic document file selections, bank details and proof, restaurant profile/menu item, operating hours with add/remove shift, review, submission, under-review status, rejected status/reason, approved status, demo login and dashboard. Order Accept, Mark ready and Reject worked. Form data survived client navigation.

Required-field validation was checked. The final build also rejected mismatched account numbers when the bank step was accessed independently before other setup steps.

No application warnings/errors appeared in the final browser console check. Browser-extension metadata errors were not application errors.

## Design preservation

`src/app/globals.css` matches the input `src/styles.css` byte-for-byte. The original central MUI theme values and JSX screen layout/classes were retained and separated into typed components. `docs/preview.jpg` shows the final Next.js screen. The reordered Profile/Hours steps match the latest explicit request.

## Limits

Browser interaction testing used the production build through this environment's preview service. The development-server startup was verified separately; the remote proxy did not serve the Next.js dev client reliably, so production was used for interaction checks. No live backend calls or real credentials/documents were used. Mobile/tablet CSS was retained but a separate mobile viewport/browser run was not performed. Server authentication/authorization and session restoration require the real backend contract.
